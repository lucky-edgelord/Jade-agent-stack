Sites

The site spec, templates, themes, building, previewing and deploying to Jade Agent Base.

A site is one file, jade.site.yaml, compiled to static HTML that loads Jade Agent UI/UX from its CDN. With a backend, the same spec also sets up Jade Agent Base: collections, modules, sign-in providers, models, plans and billing.

Templates

A template supplies pages and backend defaults. Pages in the spec replace the template's page at the same path; backend lists (collections, providers, models, plans) merge by name. jade site templates lists them.

Reusing a design

A settled design does not need rebuilding. Save it once and start new sites from it:

jade site template save house --about "Our look: ocean theme, pricing, account"   # → ~/.config/jade/templates/house.yaml
jade site template save house --project                                           # → ./templates/house.yaml (commit it)
name: Second product
tagline: Same look, new idea.
template: house          # or a path: template: ../brand/site.yaml

Templates are looked up in ./templates, then your own, then the built-in ones; a template may itself name a template to build on. Saved UI (a dashboard, a calculator) can live in a file and be reused by a surface section: {type: surface, file: dashboards/sales.yaml}.

Themes

jade site themes lists them: jade, midnight, paper, contrast, sunset, ocean, forest, rose, mono, neon, slate, terminal. Each has a light and a dark palette, a font and a radius. Visitors switch with the theme toggle in the nav.

Field shorthand: name:type! (! = required). Types: text, email, url, number, bool, date, json, editor, select, file, relation, textarea, checkbox. Rule shorthands: anyone, users (signed in), owner (adds a user relation), admin (no rule: superusers only), or a PocketBase rule.

Build, preview, deploy

CommandDoes
jade site checkvalidates and compiles in memory; lists warnings
jade site build [--out dist]writes index.html per page (/pricing → pricing/index.html), 404.html, sitemap.xml, robots.txt
jade site preview [--port 8080]builds and serves on localhost
jade site planthe deploy as a list of Base calls; secrets as placeholders; makes none
jade site deploy [--yes]runs the deploy as a playbook through the harness

A deploy is a generated playbook: approvals apply, every mutation has a content-hash idempotency key (deploying the same thing twice changes nothing), the run uses a short-lived task credential with only the scopes it needs, and an interrupted deploy resumes where it stopped. Secrets come from the environment variables the spec names.

From Python

import jade
site = jade.Site("Acme AI", tagline="Embeddings for every app.", template="saas")
site.page("/", "Home").add("nav").add("hero").add("pricing").add("footer")
site.collection("waitlist", "email:email!", create="anyone", list="admin")
site.build("dist")
