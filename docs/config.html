Configuration and secrets

jade.config.yaml keys, discovery, the OS keyring, and the init wizard.

Discovery

$JADE_CONFIG, else the nearest jade.config.yaml from the working directory upward.

Keys

KeyTypeDefaultMeaning
versionint1config format
targets.base.urlURLnoneJade Agent Base
targets.base.tokenstringjade.<host>keyring name of the agent token
targets.base.credentials{ttl, enabled}{ttl: 15m, enabled: true}task credentials for playbooks
targets.vault.urlURLnoneVault's HTTP API
targets.vault.tokenstringjade.<host>keyring name
targets.vault.accept_legacyboolfalsediagnosis only
targets.kit{ollama, model, features}nonedefaults for Kit pages
models{provider, url, key, fast, strong}nonethe model for agent --target base
approvalsmapping{}see harness
defaults.timeout / defaults.chat_timeoutseconds30 / 300call timeouts
secrets.fileboolfalseallow the 0600 file store
playbooks.routes{tool: target}{}resolve tools two targets have

Unknown keys are errors. A URL with a token in it is refused.

The wizard

jade init runs environment, targets, auth, models, permissions, smoke test, write. --yes takes defaults, --answers FILE (JSON) or --json runs headless, --skip-<step> and --only=<step> select steps, --restart forgets earlier answers (~/.config/jade/init-state.json). Permissions default to read-only and become approval patterns. A failed smoke test leaves the previous file as it was.
